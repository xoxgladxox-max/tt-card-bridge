# tt-card-bridge 功能节点树

本文件记录插件有哪些功能、代码在哪、当前状态，以及作者的决定和来源。改功能时同步更新本文件。

状态取值：

- 早期已有：本轮对话之前就有的功能，本轮没有改动，作者没有在本轮手测
- 已部署待手测：代码已改、单元测试通过、已部署，作者还没测
- 有缺陷：已发现问题，还没修
- 计划中：作者已同意，还没写代码
- 作者测过：作者手测通过（目前没有）

文件简称：`svc` = `src/sync-service.mjs`，`eng` = `src/sync-engine.mjs`，`ad` = `src/file-sync-adapter.mjs`，`ids` = `src/world-entry-ids.mjs`，`ui` = `extension/settings.js`，`idx` = `extension/index.js`

## 5 自动同步

只管酒馆当前打开的那张卡和那本世界书，每 2 秒一轮。

**每一处改动都由作者确认后才写（2026-10-27 作者决定）。** 每轮只读：把工程、酒馆和上次同步存下的基线三方对比。两边一致时只更新基线记录；有差异时这张卡状态改为「有改动待确认」，面板列出清单，任何一边都不写。

- 清单逐项给出建议：只改了工程的建议用工程，只改了酒馆的建议用酒馆，两边都改的不给建议，必须选。
- 每项显示工程文件和酒馆文件的修改时间，只作参考，不按时间自动选边。酒馆的时间是整张卡或整本世界书文件的时间，不是单条的。
- 作者可以逐项选（工程 / 酒馆 / 手写），也可以选「整卡以文件为准」或「整卡以酒馆为准」；都先列清单确认，按备份设置备份后再执行，执行后复核。
- 断连、关后台很久后再接上：基线存在 `.card-forge/tavern-sync.json`，不丢；照样逐项比对、列清单确认。
- 手动的推送、拉回、MCP `sync_now` 由调用者明确发起，算作确认，不在此列。
